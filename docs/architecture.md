# 아키텍처

## 목적

Dino Ovum은 dino-nest의 공통 기능과 디자인을 두 패키지로 분리합니다. 사용자는 자신의 문서·브랜딩·설정을 유지하면서 패키지 업데이트로 공통 개선 사항을 받습니다.

이 문서는 목표 구조를 설명합니다. 패키지 구현은 아직 시작하지 않았습니다. 기준은 로컬에서 확인한 dino-nest의 `a1fb98a` 커밋이며, 구체적인 구현 순서와 남은 결정은 [구현 계획](./implementation-plan.md)에 정리합니다.

## 저장소 경계

- **dino-ovum**: `@dino-ovum/preset`과 `@dino-ovum/theme`을 개발·배포하는 저장소이며 개발·검증용 사이트를 포함합니다.
- **dino-nest**: 사용자가 복사하는 GitHub 템플릿입니다. 최종적으로 사용자 사이트 파일과 패키지 의존성을 보관합니다.
- 사용자 템플릿에는 패키지 개발 소스와 검증용 사이트를 포함하지 않습니다.

구현 과정에서 만들 디렉터리를 포함한 목표 구조입니다.

```text
dino-ovum/
├── packages/
│   ├── preset/
│   │   ├── package.json
│   │   └── src/
│   │       ├── index.js
│   │       ├── config.js
│   │       └── plugins/
│   └── theme/
│       ├── package.json
│       └── src/
│           ├── index.js
│           ├── theme/
│           ├── app/
│           ├── assets/
│           └── translations/
├── website/                     개발·검증용 사이트
├── public/                      이 저장소의 프로젝트 브랜딩
├── docs/                        한국어 설계·계획 문서
├── language/                    영어·한국어·일본어 README
├── package.json
└── pnpm-workspace.yaml

dino-nest/                      사용자용 템플릿
├── documents/                  문서와 문서 번역
├── public/                     사이트 로고·이미지
├── src/
│   ├── css/custom.css           사용자 스타일
│   ├── pages/                  필요한 경우 추가하는 페이지
│   └── theme/                  필요한 경우 교체하는 컴포넌트
├── docusaurus.config.js         사이트 설정
├── package.json
└── pnpm-lock.yaml
```

루트의 `public/`은 Dino Ovum의 브랜딩 이미지 위치입니다. 검증용 사이트의 이미지, theme 패키지에 포함할 폰트와는 역할이 다릅니다.

## 사용자 시나리오와 내부 처리

### 사이트 생성과 커스텀

```text
사용자가 dino-nest를 복사
  → 문서·사이트 설정·로고·사용자 CSS 수정
  → 의존성 설치
  → 사이트 빌드
      → 설정 도우미가 공통 기본값과 사이트 설정 조합
      → preset이 문서·검색·PWA·공통 플러그인 등록
      → 플러그인이 탐색·최근 업데이트 데이터 생성
      → theme이 생성 데이터와 사용자 문서로 화면 구성
  → 빌드 결과 배포
```

문서와 커스텀은 사이트에서 관리하고, 공통 동작과 화면은 패키지에서 관리합니다. 최초 분리에서는 기존 화면과 기능을 유지합니다.

### 공통 업데이트 수신

```text
관리자가 dino-ovum의 공통 코드 수정
  → 검증 후 새 패키지 버전 배포
  → 사용자 저장소에 의존성·잠금 파일 업데이트 PR 생성
  → CI에서 사용자 문서로 사이트 빌드
  → 사용자가 PR 병합
  → 호스팅에서 재빌드·배포
```

업데이트 PR에는 Dependabot을 연결하는 방향입니다. 자동 병합은 별도 결정 사항입니다. 개발 저장소에 push하는 것만으로 사용자 사이트가 바뀌지는 않습니다. 기존 템플릿 사용자는 패키지 기반 구조로 최초 한 번 이전해야 합니다.

## 패키지 역할

### @dino-ovum/preset

- 문서 인스턴스, 사이드바 생성, 검색, Sass, PWA, theme을 등록합니다.
- 탐색·최근 업데이트·생성 모듈 호환 플러그인을 관리합니다.
- 최상위 사이트 기본값과 preset 등록을 조합하는 설정 도우미를 제공합니다.
- 사용자 문서와 커스텀 파일은 사용자 사이트 기준으로, 패키지 내장 파일은 패키지 기준으로 경로를 해석합니다.

설정 도우미의 공개 함수명과 옵션 형태는 아직 결정하지 않았습니다. 사용자 값이 기본값보다 우선하며, 메뉴·플러그인 배열의 추가 및 교체 규칙과 선택 기능의 활성화·비활성화 동작을 명시해야 합니다.

### @dino-ovum/theme

- 공통 React 컴포넌트·훅·프로바이더·레이아웃·스타일을 관리합니다.
- Docusaurus 테마 컴포넌트를 확장합니다.
- 공통 폰트와 기본 UI 번역을 필요한 고지와 함께 배포합니다.
- 내부 폴더를 노출하지 않는 안정적인 사용자 MDX용 컴포넌트 경로를 제공합니다.
- 사용자 CSS와 의도적인 컴포넌트 교체를 지원합니다.

사용자가 교체한 컴포넌트 영역에는 패키지 개선이 가려질 수 있습니다. 템플릿의 로컬 테마에는 실제로 필요한 교체만 남깁니다.

## 기존 코드의 분리 기준

- `src/config/site.js`: 사이트 이름·주소·선호 설정과 공통 등록·기본값을 분리합니다.
- `src/config/plugins/`, 문서 인스턴스·사이드바 설정: 공통 구현은 preset으로, 사이트별 입력값은 사이트에 둡니다.
- `src/app/`과 현재 `src/theme/`: 공통 화면 구현을 theme으로 옮깁니다.
- `src/app/styles/`: 기본 디자인은 theme으로 옮기고, 그 뒤에 적용하는 사용자 스타일 파일을 만듭니다.
- `public/`: 사이트 로고·이미지는 사이트에, 공통 폰트는 라이선스와 함께 theme에 둡니다.
- `documents/_translations/`: 문서 번역은 사이트에 남기고, 기본 UI 메시지를 분리해 사용자 재정의를 지원합니다.
- `src/pages/`: 페이지별 역할을 확인합니다. 공통 최근 업데이트 페이지와 사용자가 만든 페이지는 관리 위치가 다릅니다.

라우트·날짜·문서 위치 도우미는 현재 빌드 플러그인과 화면이 함께 사용합니다. 이동 전에 한 곳의 관리 주체와 공개 경계를 정하고, 중복 구현이나 preset/theme 사이의 순환 의존성을 피합니다.

## 정리해야 할 참조

1. 패키지 내부의 `@site/src/app/...` 의존을 내부 import로 바꿉니다. 사용자 MDX에는 공개 컴포넌트 경로를 제공하며 정확한 이름은 별도 결정합니다.
2. `@theme-original`로 감싼 컴포넌트를 이동 후 테마 계층에서 각각 검토합니다. `@theme-init` 같은 기본 테마 참조가 적합한지 검증하며 일괄 치환하지 않습니다.
3. 사이드바·CSS·폰트·번역 경로를 해당 파일의 관리 위치 기준으로 해결하고, 저장소 밖에 설치한 패키지에서도 검증합니다.
4. PWA 메타데이터·아이콘·manifest 경로·배포 경로를 사용자 설정에 연결합니다.
5. Agentation 활성화 방식을 정합니다. 현재 개발 환경 전용 동작이 모든 사용자 사이트의 필수 조건이 되지 않도록 합니다.

## 패키지 업데이트의 범위

패키지로 공통 실행·빌드 코드를 업데이트합니다. 사용자 문서, 저장소 README, 복사된 배포 workflow, 로컬 컴포넌트 교체 파일을 자동 수정하지는 않습니다. 이 파일들의 변경에는 별도 이전 안내가 필요합니다.

첫 완료 지점은 실제 배포 형태의 패키지를 사용하는 검증용 사이트가 정상 동작하는 것입니다. 전체 완료 지점은 dino-nest가 패키지 기반으로 전환되고, 사용자의 문서와 커스텀을 유지하면서 의존성 업데이트로 공통 변경을 받는 것입니다.
