# 구현 계획

## 기준과 현재 상태

2026-11-10 로컬에서 확인한 dino-nest의 `a1fb98a` 커밋을 기준으로 합니다. 이전 세션에서는 공용 스타터 기본값, 다국어 Specifications 배지, 1개 커밋을 유지한 push까지 완료했습니다. 공통 구현은 아직 dino-nest에 있습니다.

현재 Dino Ovum에는 프로젝트 문서와 브랜딩이 있습니다. 패키지 구현, 의존성 명세, workspace 설정, 실행 가능한 개발 명령은 아직 없습니다. 패키지 배포 여부와 `@dino-ovum` npm 범위의 소유권도 확인하지 않았습니다.

결정된 저장소·패키지 역할은 [아키텍처](./architecture.md)에 정리합니다. 이 문서는 구현 작업을 추적하며, 패키지를 바로 설치할 수 있다는 의미가 아닙니다.

## 1. 공개 사용 방법 정의

- [ ] 사이트 이름·URL·배포 경로·로고·언어·문서·메뉴·사용자 CSS·기능 스위치를 받는 설정 도우미의 공개 함수와 옵션을 정합니다.
- [ ] 설정·플러그인·메뉴의 우선순위와 확장 규칙을 정합니다.
- [ ] 홈 제목과 문서 표를 포함한 MDX용 공개 컴포넌트 경로를 정합니다.
- [ ] 기본 UI 번역과 문서 번역을 분리하고 사용자 재정의 방식을 정합니다.
- [ ] 공통 라우트·날짜·문서 위치 도우미와 공통 페이지의 관리 위치를 순환 의존성 없이 정합니다.
- [ ] PWA와 Agentation 등 개발 도구의 기본 활성화 여부를 정합니다.

**완료 기준:** 사용자 커스텀 시나리오와 패키지 설정 흐름을 구체적 예제로 문서화하고, 코드를 분리하기 전에 공개 이름과 동작을 확정합니다.

## 2. 패키지 개발 환경 구성

- [ ] `packages/preset`, `packages/theme`, `website`와 pnpm workspace 설정을 만듭니다.
- [ ] 패키지 진입점·공개 경로·배포 파일·의존성 관리 주체·Docusaurus/React 호환 범위를 정의합니다.
- [ ] 루트와 검증용 사이트는 비공개 패키지로 두고, 의도한 두 패키지만 배포 대상으로 설정합니다.
- [ ] 개발·검증 스크립트를 만들고 실제로 동작하는 명령을 문서화합니다.
- [ ] 패키지 라이선스 값을 `Unlicense`로 설정하고 배포물에 라이선스를 포함합니다. 가져온 코드·폰트·의존성의 해당 고지는 유지합니다.

분리 기준인 dino-nest 명세에는 Docusaurus `3.10.1`, React `^19.0.0`, pnpm `10.5.2`, Node.js `>=24.22.1 <25`가 있습니다. 이는 원본 프로젝트의 값이며 Dino Ovum이 선언하거나 검증한 호환 범위는 아직 아닙니다.

**완료 기준:** 검증용 사이트가 명확한 의존 관계에 따라 두 로컬 패키지를 사용합니다.

## 3. 공통 기능과 화면 분리

- [ ] `site.js`를 사용자 설정, 설정 도우미, preset 등록으로 나눕니다.
- [ ] 공통 플러그인·문서 인스턴스 처리·사이드바 생성을 preset으로 옮깁니다.
- [ ] `src/app`과 `src/theme`의 공통 구현을 theme으로 옮깁니다.
- [ ] 사이트 내부 경로에 묶인 import를 바꾸고 기본 테마를 감싸는 참조를 각각 검증합니다.
- [ ] CSS·폰트·기본 UI 번역을 패키지에 포함하고, 기본 스타일 다음에 사용자 CSS를 적용합니다.
- [ ] PWA 메타데이터와 경로를 사용자 설정에 연결합니다.
- [ ] 기존 문서 탐색·검색·최근 업데이트·다국어·화면 동작을 유지합니다.

**완료 기준:** 검증용 사이트에 공통 `src/app`이나 공통 테마 교체 파일의 로컬 복사본이 없어도 빌드됩니다.

## 4. 실제 배포물 검증

- [ ] 패키지 압축 파일을 만들고 진입점·의존성·에셋·번역·라이선스 포함 여부를 확인합니다.
- [ ] workspace 연결이 적용되지 않는 별도의 최소 사이트에 두 압축 파일을 설치합니다.
- [ ] 영어·한국어·일본어 문서를 빌드하고 언어 전환을 확인합니다.
- [ ] 프로덕션 미리보기에서 검색·탐색·최근 업데이트·반응형 화면·밝은/어두운 테마를 확인합니다.
- [ ] 루트가 아닌 하위 경로 배포를 포함해 PWA 메타데이터와 오프라인 동작을 확인합니다.
- [ ] 문서·로고·사이트 이름·CSS와 의도적인 컴포넌트 교체 한 곳을 사용자 방식으로 수정합니다.
- [ ] 눈에 보이는 공통 개선을 담은 두 번째 패키지 버전을 설치하고 사용자 수정이 유지되는지 확인합니다.

**완료 기준:** 공통 소스 파일을 복사하지 않고 패키지 버전 변경만으로 개선이 전달됩니다. 이것이 첫 기능 완료 지점입니다.

## 5. 템플릿과 배포 흐름 연결

- [ ] npm 범위 소유권을 확인하고 최초 버전과 배포·버전 관리 방식을 정합니다.
- [ ] preset과 theme의 의존 관계가 정상인 호환 버전을 배포합니다.
- [ ] dino-nest를 사용자 사이트 파일과 배포된 패키지 의존성 중심으로 정리합니다.
- [ ] 예제 MDX import를 바꾸고 패키지 적용을 가리는 공통 로컬 테마 파일을 제거합니다.
- [ ] 기존 템플릿 사용자의 최초 이전 방법을 문서화합니다.
- [ ] 의존성 업데이트 PR과 사이트 빌드 CI를 설정하고 호스팅 재빌드 흐름을 정합니다.
- [ ] 릴리스 안내에서 복사된 workflow·설정 변경과 패키지로 전달하는 변경을 구분합니다.

**완료 기준:** dino-nest로 생성한 프로젝트가 배포된 패키지를 설치해 빌드되고, 검증된 패키지 업데이트 PR을 받습니다. 자동 병합은 최초 범위에 포함하지 않습니다.
