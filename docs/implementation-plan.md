# 구현 계획과 상태

## 기준과 현재 상태

dino-nest의 `aa0335e1864457f7f578256a6e177d0b6cb42dca` 커밋을 기준으로 공통 소스를 분리했습니다. 두 패키지의 초기 버전은 0.1.0이며 루트와 검증용 사이트는 private입니다. 원본 dino-nest 저장소의 소스나 미커밋 작업은 변경하지 않았습니다.

공개 API는 [설정 안내](./configuration.md), 저장소 경계는 [아키텍처](./architecture.md), 실행 명령은 [개발 안내](./development.md)에서 관리합니다. 두 패키지 0.1.0은 2026-11-10 npm에 공개했습니다. npm 계정 이전과 dino-nest 전환이 남아 있습니다.

- [x] 순수 계산 도우미를 `@dino-ovum/theme/utils`로 제공해 순환 의존성을 피했습니다.

- [x] npm org `dino-ovum`을 만들고 공개 권한을 확인했습니다. 현재 owner는 `4bee` 한 명이며 2FA는 `auth-and-writes`입니다.
- [x] `@dino-ovum/theme@0.1.0`, `@dino-ovum/preset@0.1.0`을 이 순서로 공개했습니다. 배포 소스는 `91f19ac` 커밋입니다.
- [x] 빈 사이트에 레지스트리의 `@dino-ovum/preset@0.1.0`만 설치해 세 언어 빌드가 통과하는 것을 확인했습니다.
- [x] 공개 전 dino-nest 복사본 리허설에서 다국어 홈의 홈 메뉴 활성 표시 결함을 찾아 고쳤습니다.

2FA 배포는 브라우저 승인을 기다려야 하므로 대화형 터미널에서 실행합니다. 한 번 공개한 버전 번호는 unpublish 후에도 다시 사용할 수 없습니다.

## 6. npm 계정 이전 — 후속 작업

패키지는 개인 계정이 아니라 org `@dino-ovum`에 속하므로 계정을 바꿔도 다시 배포할 필요가 없습니다. 기존 계정은 새 owner를 확인한 뒤에만 삭제합니다.

- [ ] 새 npm 계정을 만들고 2FA를 설정합니다. 기존 계정과 이메일이 겹치지 않도록 `+` 별칭 주소를 쓰거나 기존 계정의 이메일을 먼저 바꿉니다.
- [ ] 기존 계정에서 `npm org set dino-ovum <새 계정> owner`로 새 계정을 owner로 추가합니다.
- [ ] `npm org ls dino-ovum`에서 두 계정이 모두 owner인지 확인합니다.
- [ ] 기존 계정 `4bee`를 삭제합니다.

org의 유일한 owner인 계정은 삭제할 수 없습니다. 삭제한 계정 이름은 30일 후 다른 사용자가 등록할 수 있습니다.

## 7. dino-nest 연결 — 후속 작업

dino-nest는 레지스트리에 공개된 버전을 의존합니다. `link:`나 압축 파일 경로를 남기지 않습니다.

- [ ] dino-nest 의존성을 `@dino-ovum/preset@0.1.0`으로 바꾸고 `docusaurus.config.js`를 `createDinoConfig`로 전환합니다.
- [ ] 패키지와 중복되는 `src/app`, `src/theme`, `src/config` 복사본을 제거합니다.
- [ ] 세 언어 `home.mdx`의 import를 `@theme/DinoOvum/HomeHeading`으로 바꾸고 `SITE_ROUTES` 참조를 경로 문자열로 바꿉니다.
- [ ] 브라우저에서 홈, 언어 전환, 다크 모드, 검색, 모바일 메뉴를 확인합니다. 이전 빌드의 서비스 워커가 남아 있으면 해당 미리보기 주소의 등록을 해제한 뒤 확인합니다.
- [x] 기존 템플릿 사용자를 위한 [최초 이전 안내](./migration.md) 작성.
- [ ] 템플릿의 의존성 업데이트 PR·사이트 빌드 CI·호스팅 재빌드 연결.
- [ ] 첫 릴리스에서 패키지 변경과 사이트 파일의 수동 이전 항목 구분.

로컬 패키지 소스를 `link:`로 연결하면 preset이 이 저장소의 `node_modules`에서 Docusaurus 의존성을 찾아 같은 모듈이 두 벌이 됩니다. 리허설에서 `Cannot mix different versions of joi schemas`로 빌드가 실패했습니다. 공개 전 검증은 압축 파일 설치를 사용합니다.

이 저장소의 커밋·push는 npm 공개나 사용자 사이트의 자동 업데이트를 뜻하지 않습니다. 템플릿 전환 시 사이트별 커스텀을 먼저 확인하고, 자동 병합은 별도로 결정합니다.
